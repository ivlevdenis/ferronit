# Changelog

Все значимые изменения Ferronit (до 0.9.0 — Ferrox), от новых версий к старым.
Теги ведутся с 0.8.1; более ранние итерации (прототип Velox) здесь не перечислены.
Версия живёт в двух файлах и меняется вместе: `ferronit/__init__.py::__version__` и `ferronit-rs/Cargo.toml`.

## 0.23.0 — 2026-10-27

**Добавлено**
- Неблокирующее структурированное логирование (`ferronit.contrib.logging`):
  протокол `LoggerProtocol` (debug/info/warning/error/critical), основная реализация
  `Logger` — очередь + фоновый поток-писатель, msgspec-сериализация, гарантия доставки
  (`flush()`/`shutdown()` + `atexit`); `LogRecord` (msgspec.Struct), `JsonFormatter`/
  `TextFormatter`, `StdlibLogger` (дефолт), `LogConfig`. `Ferronit(logger=...,
  access_log=True)` — инъекция логгера; access-log (`event`, method/path/status/
  duration_ms) и error-log с трейсбеком. Доки — `docs/logging.md`, тесты —
  `tests/test_logging.py`.

## 0.22.0 — 2026-10-22

**Добавлено**
- Структурированные ошибки входа: каждый отказ отдаёт один JSON-конверт
  `{"code", "message", "errors"}`, где `errors` — непустой массив с кодом на каждую
  ошибку. Ошибки полей несут `field` (точечный путь `addr.zip`, `tags[0]`), ошибки
  «не полей» его не несут (битый JSON, корень не объект, 415, 413, 404, 500).
  Тело-модель валидируется повторным обходом полей, поэтому отдаются ВСЕ ошибки, а
  не первая; query-модель сохраняет мягкий откат к default и собирает ошибки
  обязательных полей. Коды: `missing`, `invalid_type`, `invalid_value`, `too_small`,
  `too_large`, `too_short`, `too_long`, `not_multiple_of`, `pattern_mismatch`,
  `invalid_enum`, `invalid_json`, `not_found`, `unsupported_media_type`,
  `body_too_large`, `internal_error`. Из хендлера можно поднять свои:
  `raise ValidationError([FieldError("email_taken", "...", "email")])`. Модуль —
  `ferronit/errors.py`, доки — `docs/errors.md`, тесты — `tests/test_validation_errors.py`.

**Изменено**
- asyncpg больше не обязательная зависимость: драйвер PostgreSQL переехал в extra
  `ferronit[postgres]` (рядом с `[mysql]` и `[sqlite]`). `ferronit.contrib.rawdb`
  импортирует драйвер лениво, при создании пула, поэтому слой данных импортируется
  без установленного asyncpg, а его отсутствие даёт `ModuleNotFoundError`
  с подсказкой `pip install 'ferronit[postgres]'`.

## 0.21.0 — 2026-10-19

**Добавлено**
- SQL по стандарту: CTE (`sql.With`/`sql.Cte`, включая `RECURSIVE`) — как оператор (верхний
  уровень, подзапрос, вокруг составного) и как выражение; множественные операции
  `UNION`/`UNION ALL`/`EXCEPT`/`INTERSECT` со своими `ORDER BY`/`LIMIT` у составного; оконные
  функции `Func(...).over(partition_by=…, order=…)`; `CAST` с картой типов диалекта; `AS` для
  выходной колонки; алиас источника `FROM`, поэтому само-джойн таблицы выразим без подзапроса.
- Подзапросы в `IN`/`NOT IN`/`EXISTS` и коррелированные, подзапрос как скаляр в сравнении;
  `Column.in_`/`not_in` принимают подзапрос.
- DDL: `CreateTable`, `AddColumn`, `CreateIndex`, `DropTable`, `Column` с типом, `NOT NULL`,
  `DEFAULT`, `PRIMARY KEY` — схема описывается теми же узлами, что и запросы.
- `RETURNING` настраивается диапазоном колонок; там, где сервер его не умеет, ключи
  не выдумываются, а запись уходит путём по одной строке.
- Пример файла миграции `examples/migrations/0001_orders.py`; в `bench/` — замеры без HTTP
  (против SQLAlchemy Core/ORM и сырого asyncpg), CPU под HTTP-нагрузкой, батчинг и сохранность
  (опыт с SIGKILL), транзакции при 50 клиентах.

**Изменено**
- Диалект отказывает вместо неверного SQL: `EXCEPT ALL`/`INTERSECT ALL` и скобки вокруг ветвей
  составного на SQLite, `CAST` в недоступный тип — `DialectError`.
- README (EN/RU) и `docs/benchmarks.md`: числа приведены к свежему замеру, текст «почему быстро»
  переписан без преувеличения — на чтении строк BlackSheep впереди (5 674 против 7 725 req/s
  на `limit=100`), на ping паритет (95 119 против 88 951), разрыв с FastAPI/Django остаётся
  порядковым.
- `docs/data/rawdb.md`: транзакции при многих клиентах — пул разводит клиентов, изоляция и откат
  соседей, конкурентная арифметика только атомарным `UPDATE`, правила «один UoW на запрос».

**Исправлено**
- Шаблон маршрута с более чем 25 параметрами отклоняется `ValueError`: паника matchit через FFI
  выходила наружу `PanicException` (наследник `BaseException`) мимо документированного отказа.

## 0.20.0 — 2026-10-15

**Добавлено**
- Генератор SQL умеет все типы джойнов: `sql.Join(table, on, kind=…, alias=…)` с `LEFT`/`INNER`/
  `RIGHT`/`FULL`, производные таблицы `sql.Subquery(statement, alias)` и колонки с квалификацией
  `sql.Ref(column, alias)`. В слое данных открыт `Query.join(..., kind=…)` (по умолчанию `LEFT`),
  а `fetch_joined()` возвращает `(родитель, [дети]…)` как и раньше.
- Диалект отказывает вместо неверного SQL: `FULL JOIN` на MySQL → `DialectError`, потому что
  `FULL OUTER JOIN` у сервера нет; соединение таблицы без `ON`/алиаса и подзапрос с двумя алиасами
  тоже отклоняются.
- Тесты джойнов на трёх настоящих движках (PostgreSQL, MySQL, SQLite) — по типам джойна,
  с проверкой отказа MySQL и с подзапросом в качестве источника `FROM`.

**Изменено**
- JOIN-обёртка слоя данных собирается узлами дерева вместо строкового пост-процесса: родительский
  `SELECT` уходит в подзапрос `t0`, колонки квалифицируются `Ref`, условие `ON` — узлом; SQL по
  первичному ключу со связями компилируется один раз при создании репозитория.
- `Compare` принимает узел справа — выражение рендерится как SQL, а не связывается параметром;
  так записывается сравнение колонки с колонкой в `ON`.
- Компилятор подзапросов держит нумерацию параметров непрерывной: значения внутреннего и внешнего
  запроса идут в один список.

## 0.19.0 — 2026-10-15

**Добавлено**
- **Генератор SQL на дереве выражений** (`ferronit.contrib.sql`): сравнения, функции
  (`count(*)`, `sum(age)`), `IN`/`LIKE`/`BETWEEN`, логические узлы, группировки
  (`GROUP BY`, `HAVING`, `DISTINCT`), операторы `SELECT`/`INSERT`/`UPDATE`/`DELETE`.
- **Диалекты**: PostgreSQL (`$N`, `ANY`, `ILIKE`, `RETURNING`, `ON CONFLICT … EXCLUDED`),
  SQLite (`?`, двойные кавычки, `RETURNING`, `excluded.`), MySQL (`%s`, обратные кавычки,
  `IN (…)` без `ANY`, без `RETURNING`, `ON DUPLICATE KEY UPDATE`). Неподдерживаемая движком
  фича даёт `DialectError`, а не молча неверный SQL.
- **Бэкенды MySQL и SQLite**: слой данных работает на трёх движках, движок выбирается схемой
  DSN в `create_pool` (`postgresql://`, `mysql://`, `sqlite://`); extras `mysql` и `sqlite`.
- `RawModelRepository.fetch_rows()` — сырые строки для проекций и агрегатов;
  у `Query` — `distinct()`, `group_by()`, `having()`, а `columns()` принимает узлы.
- Тестовые БД: `docker-compose.dbs.yml` + `scripts/dbs_up.sh` (MySQL 8.4 на :3307);
  SQLite контейнера не требует — прогоны идут в процессе.

**Изменено**
- `rawdb`/`rawmodel` компилируют SQL под диалект соединения. Для движков без `RETURNING`
  ключ берётся у драйвера, а строка дочитывается точечным запросом мимо identity map
  (иначе `upsert`/`update` возвращали устаревший объект); связи грузятся `IN (…)` вместо
  `= ANY($1)`; `save_many` на MySQL идёт по строке (один round-trip на запись).
- Модуль `sqlast` переименован в `sql` — он не только дерево: в нём диалекты и компиляция.

**Тесты**: 333 (было 273) — побайтный паритет SQL со старым генератором, рендер на трёх
диалектах, прогон репозиториев на живых PostgreSQL, MySQL и SQLite.


## 0.18.0 — 2026-10-14

**Добавлено**
- гибридная загрузка связей `Relation`: точечное чтение (`get`/`fetch_one`) — одним
  `LEFT JOIN` (1 round-trip вместо 2), массовое (`list`/`fetch`) — отдельным
  `SELECT … WHERE fk = ANY($1)` (без дублирования родительских колонок).
- явный `Query.join(other, fk=… | on=col==col)` + `RawModelRepository.fetch_joined()` —
  multi-table `LEFT JOIN`, результат `(родитель, [дети])`.

**Изменено**
- `Column` знает свою модель; сравнение колонок `A.c.x == B.c.y` даёт `OnPair`.
