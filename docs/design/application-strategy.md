# Velox — стратегия применения (заметки)

> Дата: 30 авг 2026. Статус: обсуждение, просто зафиксировано.

## Где Velox силён

- Высоконагруженный JSON API (88k req/s, Rust-роутинг без деградации)
- Enterprise с требованиями порядка: DDD/CQRS/Hex из коробки + ASVS L1 (банки, финтех, госсектор)
- LLM-приложения: быстрый JSON + SSE-стриминг + будущий LLM-слой
- Реалтайм: WebSocket, SSE (уведомления, стримы)
- Внутренние инструменты: быстрый старт с чистой архитектурой
- Замена легаси-монолита: поштучная миграция сервисов

## Архитектурные роли

1. BFF (Backend for Frontend) — тонкая агрегация, идеальное первое применение
2. Сервис в микросервисах — там, где нагрузка высокая, а Go не хочется
3. LLM-прокси / агентный бэкенд — стриминг токенов через SSE
4. Внутренний CRM/панель — DDD помогает при росте бизнес-логики

## Где НЕ применять

- Критична экосистема (интеграции, кадры, плагины)
- Команды без DDD-опыта — архитектура покажется сложной
- Заказчик жёстко требует FastAPI/Django — не спорить

## Стратегии внедрения

| Путь | Как | ROI |
|---|---|---|
| Внутри компании (после трудоустройства) | 1 небольшой сервис (BFF/интеграция), показать цифры | высокий |
| Заказчику | как enterprise-фреймворк с ASVS — аргумент для банков | средний (нужен пилот) |
| Портфолио | кейс для собеседований | уже работает |
| Open Source | публикация, документация, кейсы | низкий (годы) |

## Что допилить для лёгкого применения

1. Docker-образ (velox new + контейнер одной командой)
2. Миграции — Alembic-интеграция (сейчас только create_all)
3. Примеры под кейсы: BFF, LLM-чат, CRM (сейчас один e-commerce)
4. Деплой-секция в README: granian + workers + nginx

## Вывод

Реалистично: (1) внедрить в команде после трудоустройства для новых сервисов, (2) для собеседований/позиционирования. Open Source-успех — бонус, не цель.
